## Reasoning chains
- User's two objections (code fences; markdown link collision) BOTH evaporate in .txt → their preference is coherent, not random: they want a format that defines everything itself, inherits nothing.
- Extension decides what is inherited: .md = inherit markdown semantics + rendering, fight collisions; .txt = define 100% of grammar, gain monospace freedom (ASCII sketches become legal), lose rendering.
- KEY NEW INSIGHT: lenient parsing — "anything that isn't a widget marker is a note" — removes the need for any comment syntax (#, //). Fountain precedent: in Fountain, unmatched lines are action/description. Only possible because the format is lenient by design; elegantly resolves prose-vs-grammar tension. Typos silently become notes (cost of leniency — but aligns with incompleteness-as-feature).
- The .md argument is mostly ecosystem inertia + heading rendering; DESIGN.md/MKF/OKF are md because they're documents/token files, not structure specs.
- Incompleteness-as-feature (earlier): escape hatches are OK; humans fill holes.

## Key insights
- Lenient parse = zero comment syntax (Fountain-style).
- .txt removes the link-collision problem entirely.
- Container mechanics still needed for multi-widget groups + repetition.
